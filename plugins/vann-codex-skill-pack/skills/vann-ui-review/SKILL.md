# VANN UI review

Review the interface in the context of the user task it supports. Inspect the relevant components, states, and styles first; use a running app or screenshots when they are available.

Prioritize findings that affect completion of the core task. Check:

- hierarchy, labels, feedback, empty/loading/error states, and irreversible actions;
- keyboard access, visible focus, semantic controls, color contrast, and readable error messages;
- narrow and wide layouts, touch targets, overflow, and content that can grow or localize;
- consistency with nearby VANN screens, typography, spacing, and interaction patterns.

Distinguish confirmed defects from suggestions. Report findings ordered by impact, including the affected screen/component, the observed issue, why it matters, and a concrete improvement. Avoid subjective redesign proposals unless the user asks for a redesign.

If asked to implement fixes, agree on or infer a minimal scope, preserve existing product decisions, and verify the affected states afterward.
