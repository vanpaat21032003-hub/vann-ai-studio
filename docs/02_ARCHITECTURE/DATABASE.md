# Vann AI Studio V1 Database Specification

Status: proposed for architecture review. This is a data-model design only; it defines no SQL, migration, table, API, or application implementation.

## Design conventions

- Use PostgreSQL-compatible types because Supabase is the planned backend.
- Use `uuid` primary keys. Their default is generated at insert time by the database.
- Store all timestamps as `timestamptz` in UTC.
- Use `created_at` with a current-timestamp default. Use `updated_at` with the same initial default and update it through a later database or application convention.
- Use `text` for user-managed labels until a stable, shared vocabulary justifies database enums or check constraints.
- Treat a product analysis as a derived, replaceable snapshot. Its one-to-one relationship is enforced by a unique `product_id` when implemented.

## 1. `products`

**Purpose:** The canonical affiliate-product record. It is the source entity for product assets, AI analysis, and content projects.

| Column | Type | Rules and default |
| --- | --- | --- |
| `id` | `uuid` | Primary key; generated by default. |
| `title` | `text` | Required. |
| `category` | `text` | Nullable. |
| `gender` | `text` | Nullable. |
| `brand` | `text` | Nullable. |
| `color` | `text` | Nullable. |
| `material` | `text` | Nullable. |
| `status` | `text` | Required; default `draft`. |
| `notes` | `text` | Nullable. |
| `created_at` | `timestamptz` | Required; default current timestamp. |
| `updated_at` | `timestamptz` | Required; default current timestamp. |

**Foreign keys:** None. Referenced by `product_images`, `projects`, and `product_analysis`.

**Future scalability:** Add ownership/workspace scoping before multi-user support, external affiliate identifiers and source URLs when ingestion is introduced, and normalized taxonomy tables only after categories, brands, colors, or materials require controlled reporting.

## 2. `product_images`

**Purpose:** Stores ordered source, reference, and generated image records associated with a product.

| Column | Type | Rules and default |
| --- | --- | --- |
| `id` | `uuid` | Primary key; generated by default. |
| `product_id` | `uuid` | Required foreign key to `products.id`. |
| `image_url` | `text` | Required; storage URL or durable asset reference. |
| `image_type` | `text` | Required; default `source`. |
| `created_at` | `timestamptz` | Required; default current timestamp. |

**Foreign keys:** `product_id` → `products.id`.

**Future scalability:** Add asset metadata such as storage path, MIME type, dimensions, checksum, sort order, generation provenance, and soft deletion when image workflows and generated variants are implemented. Index `product_id` for product detail and project setup queries.

## 3. `models`

**Purpose:** A reusable catalog of fashion-model references used to define a project’s subject and visual direction.

| Column | Type | Rules and default |
| --- | --- | --- |
| `id` | `uuid` | Primary key; generated by default. |
| `name` | `text` | Required. |
| `gender` | `text` | Nullable. |
| `body_type` | `text` | Nullable. |
| `height` | `numeric(5,2)` | Nullable; unit must be documented before implementation. |
| `style` | `text` | Nullable. |
| `pose` | `text` | Nullable. |
| `thumbnail_url` | `text` | Nullable. |
| `reference_url` | `text` | Nullable. |
| `tags` | `text[]` | Required; default empty array. |
| `created_at` | `timestamptz` | Required; default current timestamp. |

**Foreign keys:** None. Referenced by `projects.model_id`.

**Future scalability:** Split poses and model references into related tables when a single model needs many poses, images, or consent records. Add an active/archive lifecycle instead of deleting models used by historical projects.

## 4. `styles`

**Purpose:** Reusable visual-style definitions for content projects.

| Column | Type | Rules and default |
| --- | --- | --- |
| `id` | `uuid` | Primary key; generated by default. |
| `name` | `text` | Required. |
| `lighting` | `text` | Nullable. |
| `camera` | `text` | Nullable. |
| `background` | `text` | Nullable. |
| `mood` | `text` | Nullable. |
| `created_at` | `timestamptz` | Required; default current timestamp. |

**Foreign keys:** None. Referenced by `projects.style_id`.

**Future scalability:** Add a versioned configuration field later for structured image and video-generation parameters. Preserve existing style records for reproducibility rather than mutating styles used by completed projects.

## 5. `prompt_presets`

**Purpose:** Stores reusable prompt templates for Fashion Brain and later image or motion workflows.

| Column | Type | Rules and default |
| --- | --- | --- |
| `id` | `uuid` | Primary key; generated by default. |
| `title` | `text` | Required. |
| `category` | `text` | Required. |
| `prompt` | `text` | Required. |
| `created_at` | `timestamptz` | Required; default current timestamp. |

**Foreign keys:** None in V1.

**Future scalability:** Add preset versioning, variables/placeholders, model/provider compatibility, visibility/ownership, and usage tracking. Do not directly couple presets to projects until prompt execution history is designed.

## 6. `projects`

**Purpose:** The workflow aggregate for producing affiliate content from one product, optionally using a selected model and visual style.

| Column | Type | Rules and default |
| --- | --- | --- |
| `id` | `uuid` | Primary key; generated by default. |
| `project_name` | `text` | Required. |
| `product_id` | `uuid` | Required foreign key to `products.id`. |
| `model_id` | `uuid` | Nullable foreign key to `models.id`; permits early project drafts. |
| `style_id` | `uuid` | Nullable foreign key to `styles.id`; permits early project drafts. |
| `status` | `text` | Required; default `draft`. |
| `created_at` | `timestamptz` | Required; default current timestamp. |
| `updated_at` | `timestamptz` | Required; default current timestamp. |

**Foreign keys:** `product_id` → `products.id`; `model_id` → `models.id`; `style_id` → `styles.id`.

**Future scalability:** This is the natural parent for generated images, motion jobs, publishing records, prompt runs, approvals, and workflow events. Add a JSONB configuration snapshot only when the first workflow requires it; use purpose-specific child tables for durable operational data. Index `product_id`, `model_id`, `style_id`, and likely `status`.

## 7. `product_analysis`

**Purpose:** Stores the latest structured AI-assisted interpretation of a single product.

| Column | Type | Rules and default |
| --- | --- | --- |
| `id` | `uuid` | Primary key; generated by default. |
| `product_id` | `uuid` | Required, unique foreign key to `products.id`. |
| `detected_category` | `text` | Nullable. |
| `detected_color` | `text` | Nullable. |
| `detected_material` | `text` | Nullable. |
| `detected_gender` | `text` | Nullable. |
| `keywords` | `text[]` | Required; default empty array. |
| `ai_summary` | `text` | Nullable. |
| `confidence` | `numeric(4,3)` | Nullable; implementation should constrain to 0–1. |
| `analyzed_at` | `timestamptz` | Required; default current timestamp. |

**Foreign keys:** `product_id` → `products.id`, unique to enforce one current analysis per product.

**Future scalability:** Keep this as the current-analysis projection. Introduce a separate immutable `product_analysis_runs` history table when re-analysis, multiple AI providers, source-image attribution, raw outputs, cost, and prompt traceability are required.

## Relationship and lifecycle rules

- A product can have zero or many images. Every image belongs to exactly one product.
- A product can have zero or many projects. Every project belongs to exactly one product.
- A project may select one model and one style; models and styles can be reused by many projects. Both selections remain nullable during drafting.
- A product has zero or one current analysis. Every analysis belongs to exactly one product.
- Deletion behavior must be deliberately chosen before implementation. The recommended default is to prevent deletion of products, models, or styles with dependent records, and use archival state instead.

## Future module boundary

Fashion Brain, Motion Studio, Publishing, AI Analysis, and Video Generation should attach to `projects` through dedicated child tables. This avoids overloading `projects` with provider-specific outputs, publishing state, or processing logs. Research is a separate domain and should receive its own tables rather than sharing the affiliate-workflow schema.
